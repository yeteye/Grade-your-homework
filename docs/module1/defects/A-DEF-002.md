# A-DEF-002 规范化后重复的要点被重复计权

- 被测基线：`2da8824`
- 发现人：曹浩（M202677234）
- 关联用例：A-020
- 严重程度：中；优先级：中
- 状态：已修复并回归通过
- 证据：`reports/module1/a-defects-baseline.json`，`test_a020_normalized_duplicate_rubric_is_rejected`

## 复现

向 `POST /compare_texts` 发送作答 `A`、参考答案 `AB`，要点为 `A`（权重 1）、`Ａ`（全角，权重 1）及 `Z`（权重 1）。

预期：评分匹配将 `A` 和 `Ａ` 规范化为相同关键词，重复要点应被拒绝，返回 400 且不保存记录。

实际：接口返回 200 并保存记录。两条等价要点均被命中，作为独立权重计入，返回基础分 66.67；若只保留 `A` 和 `Z`，基础分将不同。`validation.rubric` 只做 `casefold()` 去重，评分匹配则使用 `normalize()`，校验语义与实际评分语义不一致。

## 影响与修复验证

用户可通过全半角、标点等形式重复同一要点，改变最终权重。修复提交 `ec22c91` 将规范化逻辑放在共享模块，校验和实际匹配调用同一函数。`reports/module1/a-final-full.json` 中 A-020 已通过，返回 400 且未保存记录；A-013、A-015、A-016 合法要点用例通过。
